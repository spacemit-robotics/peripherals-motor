# RS485 20/26 电机驱动

`drv_uart_rs485_20_26` 实现 20 字节命令、26 字节反馈的 RS485 电机协议。
命令帧头为 `FE EE`，反馈帧头为 `FC EE`，使用 CRC32 字校验。
驱动负责 UART 收发、编解码和通信诊断，电机的单位换算参数由调用方提供。

## 分配与配置

通过 `motor_alloc_uart_with_options()` 传入设备路径、波特率、命令 ID 和选项：

| 选项 | 约束 |
| --- | --- |
| `protocol_scales.torque/velocity/position/kp/kd` | 五项必填，有限且大于零；每 SI 单位对应的线协议整数计数 |
| `model` | 可选描述标签，不用于选择换算系数 |
| `feedback_id` | 默认等于命令 ID；两者均为 0–14，同一总线中分别唯一 |
| `idle_poll` | 默认 `false`；启用后，读取未使能设备时发送失能查询帧 |
| `transaction_timeout_us` | 默认 2000，范围 100–100000 微秒 |

同一设备路径的端点共享 UART、接收流和锁，波特率必须一致。
初始化只打开和配置串口，不发送电机命令。支持 `MOTOR_MODE_IDLE`、
`MOTOR_MODE_HYBRID` 和 `MOTOR_MODE_TRQ`；其他模式、未知选项、非法系数或重复端点会报错。
五个命令数值字段按比例换算后向零截断；非有限值、负增益和整数溢出拒绝编码。

串口打开时请求 `ASYNC_LOW_LATENCY`；Linux FTDI 驱动据此使用 1 ms 接收缓存延迟。
端口不支持 serial ioctl 时允许 `ENOTTY`；其他串口配置错误会导致初始化失败。
同一总线应只由一个控制进程操作。

## 批量收发

每条总线的命令 ID 按 0 开始连续排列时，一次写入拼接帧，再通过 `ppoll`
同时等待各总线反馈。其他选择集合每轮每条总线发送一个目标帧，独立总线仍并行，
不会向未选中的设备补发命令。最多处理 64 个端点，每条总线最多 15 个。

每轮总线事务的共同截止时间取该总线各端点 `transaction_timeout_us` 的最小值；
连续批次只等待一轮，非连续集合可能需要多轮。缺帧设备保留原接收时间并返回超时；
单个端点失败不阻止其他端点的发送，包括失能命令。

主机单调时钟记录完整有效反馈的接收时间。读取缓存不会刷新时间戳；该时间不表示
设备内部采样时间，也不标识反馈对应哪次命令。

## 通信诊断

`motor_get_transport_diagnostics()` 返回每条总线累计的 RX/TX 字节、有效帧、
CRC/解码错误、重同步丢弃字节、未知 ID、读写/poll 错误及超时。
最近失败事务包含耗时、超过截止时间的时长、收发字节、有效帧数、CRC 错误数、
缺失反馈 ID 位图和 errno；后续成功不会清除此记录。
CRC 错误按候选帧计数，错误帧不更新反馈。收发路径只更新整数计数，不打印或写文件。

## 离线测试

构建时启用本驱动及 `BUILD_TESTS`，执行以下 CTest 项：

- `rs485_20_26_protocol`：帧编码、CRC、量化及非法输入。
- `rs485_20_26_uart`：伪终端收发、碎片反馈、缓存时间和超时。
- `rs485_20_26_batch`：多总线连续/非连续集合、乱序反馈、缺帧及失能发送。

测试使用伪终端，不打开物理串口。
